# Open AntiLag 0.4.0 beta 1

[Скачать экспериментальную сборку](https://github.com/dw1rf/OpenAntiLag/releases/tag/v0.4.0-beta.1) · [Стабильная 0.3.0](https://github.com/dw1rf/OpenAntiLag/releases/tag/v0.3.0) · [MIT](LICENSE)

Независимый открытый менеджер игрового профиля для Windows 10/11 x64, .NET Framework 4.8. Без сторонних библиотек, драйверов и телеметрии. Сине-серый интерфейс с тёмным заголовком, читаемыми заблокированными карточками и прокруткой на небольшом экране.

**0.4 — экспериментальная версия.** BCD, HAGS и системные приоритеты теперь входят в основную кнопку «Включить профиль», без отдельной галочки. Это не доказанная оптимизация CS2: возможны ухудшение производительности, задержки, нагрева и стабильности. Нулевой input lag не обещается. Реальное применение BCD и загрузка после него ещё не проверены на тестовом ПК; сборку нельзя считать готовой к массовому распространению как проверенный оптимизатор.

Скриншот показывает клиентскую область. Цвет системного заголовка задаётся через DWM; доступность зависит от Windows.

## Запуск

1. Завершите предыдущую копию через трей. Запустите EXE из постоянного расположения.
2. Если старый профиль активен, нажмите «Восстановить»/«Отключить» до нового включения.
3. Закройте игру, выберите дополнительные опции и нажмите **«Включить профиль»**. Подтвердите права администратора для той же учётной записи Windows.
4. После записи системных значений приложение покажет **«Нужна перезагрузка ПК»**. Сохраните работу и перезагрузите Windows самостоятельно. Программа не перезагружает ПК автоматически.
5. **«Отключить»** возвращает сохранённые значения. После изменения системной части снова нужна перезагрузка.

Первый запуск и автозапуск не применяют новый системный профиль. Закрытие окна сворачивает приложение в трей. Выход оставляет постоянные настройки; временный запрос таймера 1 мс заканчивается. Автозапуск включается отдельной галочкой; после перемещения EXE обновите его из нового расположения.

## Что входит в основную кнопку

| Настройка | Записываемое значение |
|---|---|
| Питание | Отдельная копия штатного High Performance; исходный план сохраняется. |
| HPET / BCD | Удаляет явное переопределение `useplatformclock` в текущей записи загрузки. **Физическое устройство HPET не отключается.** |
| Таймеры BCD | `useplatformtick = yes`, `disabledynamictick = yes` в той же записи загрузки. |
| HAGS | `HKLM\SYSTEM\CurrentControlSet\Control\GraphicsDrivers\HwSchMode = 2`. Запрос включения; фактическая доступность зависит от GPU, драйвера и Windows. |
| Системные приоритеты | `HKLM\SYSTEM\CurrentControlSet\Control\PriorityControl\Win32PrioritySeparation = 42` (десятичное, `0x2A`). Приоритет процесса CS2 не изменяется, Realtime не используется. |

Microsoft описывает перечисленные BCD-переключатели как отладочные параметры. Их запись не доказывает уменьшение задержки. Эти изменения действуют на всю систему, а не только на CS2. При активной или неизвестной защите BitLocker изменение BCD блокируется. Программа не отключает BitLocker, Secure Boot или другие средства защиты. Если проверить BitLocker не удалось (включая отсутствие WMI-провайдера), применение тоже прекращается. Это ограничение экспериментальной сборки.

## Дополнительные опции

| Опция | По умолчанию | Поведение |
|---|---|---|
| Game Mode | Да | `HKCU\Software\Microsoft\GameBar\AutoGameModeEnabled = 1`. |
| Отключить запись Xbox | Да | `HistoricalCaptureEnabled` и `AppCaptureEnabled` в `HKCU\Software\Microsoft\Windows\CurrentVersion\GameDVR`, `GameDVR_Enabled` в `HKCU\System\GameConfigStore` → 0. Отключается в том числе ручная запись Xbox; OBS не настраивается. |
| Мышь без ускорения | Да | `SPI_SETMOUSE` → `[0,0,0]`, исходные значения читаются через `SPI_GETMOUSE`. DPI, скорость и частота опроса не меняются. Raw Input обходит это преобразование. |
| CPU без парковки | Нет | В собственном плане только от сети: `PROCTHROTTLEMIN/MAX = 100`, `CPMINCORES = 100`. Возможен дополнительный нагрев. |
| Питание PCIe | Нет | В собственном плане только от сети: `SUB_PCIEXPRESS / ASPM = 0`. |
| Таймер 1 мс | Нет | `timeBeginPeriod(1)` до отключения/выхода. Отдельный запрос работающего приложения, не то же самое, что параметры BCD. |

Параметры CPU — запрос политик Windows, а не гарантия частоты или поведения firmware. Базовая копия High Performance содержит штатные настройки и для батареи. Game DVR зависит от версии Windows: остановите запись, закройте Game Bar и проверьте «Параметры → Игры → Записи». NVIDIA Reflex / AMD Anti-Lag настраиваются в поддерживающей их игре/драйвере отдельно.

## Сохранение и восстановление

Перед записью сохраняются точные исходные значения, включая отсутствие параметра, и идентификатор текущего загрузчика. Перед каждой попыткой записи сохраняется отметка, затем результат проверяется чтением. При ошибке выполняется обратное восстановление. Незавершённая операция остаётся доступной для повторного отката.

Системный журнал хранится в `HKLM\SOFTWARE\OpenAntiLag\SystemProfile` (значение `Journal`): запись разрешена администраторам и SYSTEM, обычным пользователям — чтение. Повышенный процесс принимает только фиксированные операции и настройки; произвольных путей из журнала нет. Системный профиль принадлежит одной учётной записи; откат из другой учётной записи или другой записи загрузчика блокируется.

Пользовательский журнал и резервные копии: `%LOCALAPPDATA%\OpenAntiLag\state.xml`, `state.xml.bak`, `events.log`. Не удаляйте их и системный журнал при активном профиле. Системная ошибка показывается отдельным окном; общий журнал может содержать только сообщение о незавершённой операции.

Если значение после включения изменили извне, откат сохраняет внешний выбор. Идентичную целевому значению стороннюю запись отличить невозможно. Пользовательские расхождения проверяются в интерфейсе; системный статус показывает сохранённую фазу, а не непрерывный аудит BCD/HAGS. «Профиль записан» не подтверждает фактическую работу HAGS или снижение задержки.

Восстановление одной настройки при ошибке не мешает попыткам восстановить остальные. Если BitLocker включён после применения, восстановление BCD также блокируется, журнал остаётся для повторной попытки. Ограничения Modern Standby и политик Windows не обходятся.

## Обновление и удаление

Старые пользовательские резервные копии 0.1–0.3 поддерживаются. Сначала восстановите предыдущий профиль, затем включите новый. **Перед переходом с 0.4 обратно на 0.3 или старее отключите профиль именно в 0.4:** старые версии не умеют восстанавливать новую системную часть.

68W AntiLag нужно закрыть. Его прежние изменения не отменяются: сохраняется состояние на момент включения Open AntiLag, а не заводские настройки Windows. Если нужные значения уже совпадали, они не записываются повторно.

Перед удалением отключите профиль, при необходимости перезагрузите ПК, выключите автозапуск и выйдите через трей. Если исходный план питания удалён извне, выберите другой план Windows и повторите восстановление.

## Сборка и проверка

```powershell
.\build.ps1
.\dist\OpenAntiLag.Tests.exe --ui-check
```

Встроенный компилятор .NET Framework, без NuGet. 49 тестов с имитацией Windows: точный откат всех пяти системных параметров, частичные ошибки, отказ записи журнала, отмена UAC, смена владельца/загрузчика, изменение BitLocker, внешние значения, прерванное применение и согласование двух частей профиля. Тест интерфейса нажимает реальные кнопки с подменённым адаптером Windows.

Проверены сборка, имитационные тесты, рендер обычного/узкого окна и увеличенных шрифтов. Схемы WMI-методов BCD прочитаны на реальной Windows. **Реальная запись BCD/HAGS, перезагрузка, автозапуск после входа и эффект в играх не проверялись.** EXE не подписан цифровой подписью.

```powershell
# Чтение пользовательских параметров без изменения Windows
.\dist\OpenAntiLag.Tests.exe --inspect
# Рендер с имитацией системы
.\dist\OpenAntiLag.Tests.exe --preview "$PWD\preview.png"
```

Основные файлы: `Engine.cs` — пользовательский профиль; `MachineEngine.cs` — системный журнал и откат; `MachineWindows.cs` — Windows/WMI и повышение прав; `ProfileController.cs` — согласование двух частей; `MainForm.cs`/`Theme.cs` — интерфейс. Исходники в `src`, тесты в `tests`.
