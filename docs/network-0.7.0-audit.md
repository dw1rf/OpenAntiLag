Работа выполнялась поверх локального `92cd112` (0.6.4). Чтение удалённого Git через `git fetch github` в этой среде завершилось ошибкой соединения; отсутствие более новых изменений на GitHub не утверждается. Переиспользуются исходные Engine/ProfileController/MachineEngine, Settings, NVIDIA/AMD, ShaderEngine и Updates. Их параметры повторно не реализованы в сетевых модулях. Из старого UI изменены только добавление страниц, перенос вкладок, ограничение окна рабочей областью экрана, DPI-размеры OptionCard и восстановление собственных QoS при выходе. Прежние проверки отката, GPU, шейдеров и обновлений остались в сборке.

## Новые компоненты

- `NetworkModels`: наблюдения, ограниченная история, математика, безопасный CSV/JSON и валидация пользовательских адресов.
- `NetworkMonitor`: ограниченный асинхронный ICMP/TCP, интерфейсы, IPv4 route lookup и диагностическая сводка с разделением фактов/признаков/гипотез.
- `GameConnections`: штатные IP Helper TCP/UDP owner-PID таблицы IPv4/IPv6. Пути получаются через QueryFullProcessImageName с PROCESS_QUERY_LIMITED_INFORMATION. Память процессов не читается.
- `DnsProbe`: ограниченный стандартный UDP DNS запрос, проверка transaction ID, question, response flags/RCODE, границ и A/AAAA-данных.
- `NetworkController`/`NetworkStateStore`: отдельные DTO, журнал, ACL, интерфейсы для fake и проверка точного результата.
- `WindowsNetworkHost`: адаптер штатных DNS Client/NetQoS командлетов и чтение DNS override по каждому семейству. Отдельный `--network` помощник с проверкой SID и системным mutex.
- `NextDnsClient`: ограниченные HTTPS-запросы официальному API, без перенаправления API key, проверка HTTP и API errors. DPAPI CurrentUser хранит ключ отдельно от журналов.
- `PerformanceMonitor`, `GameProfileManager`: CPU/RAM, сравнение одинаковых заданных интервалов, локальные профили мониторинга.
- `ToolPage`, `NetworkPage`, `TrafficPage`, `DnsPage`, `StatisticsPage`: тёмный UI, отмена измерений, отдельные подтверждения сетевой записи и ошибок.

## Модель восстановления

Для сетевого состояния выбран отдельный защищённый HKLM-журнал. Registry value обновляется целиком, предыдущий XML остаётся отдельно, результат Flush проверяется исключениями. Повреждение не маскируется пустым состоянием и не вызывает автоматическое чтение старой копии. Перед каждой попыткой записи сохраняются исходные и ожидаемые значения и флаг попытки. При восстановлении перечитывается фактическая конфигурация.

DNS сохраняется по GUID адаптера и семейству IPv4/IPv6: automatic/DHCP либо упорядоченный static override. Полученные по DHCP адреса не превращаются в static при восстановлении. QoS использует уникальные имена, ActiveStore и полный отпечаток прочитанных условий/действий политики. CIM ThrottleRateAction возвращает байт/с; параметр командлета принимает бит/с, поэтому преобразование выполняется один раз и проверено тестом.

Сторонние/неоднозначные изменения не перезаписываются, журнал сохраняется для проверки. Из-за отсутствия общей транзакции между Windows и журналом остаются два консервативных случая: неоднозначное частичное DNS-применение и сбой после создания QoS до сохранения полного отпечатка. Автоматический откат в этих случаях может потребовать ручной проверки; фиктивный успех не выдаётся.

Права администратора требуются только помощнику сетевой записи. У UI asInvoker. Сетевые записи разделяют блокировку с системными/GPU-изменениями; диагностические чтения не требуют этой блокировки. Ограничение прав, неизвестные свойства CIM, отсутствие модулей и повреждение журналов дают отказ с объяснением.

## Что остаётся ограниченным

- Нет per-process bytes/s и UDP remote endpoint: штатные endpoint-таблицы этого не дают. Число endpoints не называется нагрузкой.
- Не определяется IPv6 best route; показываются IPv6-адреса, MTU, DNS и endpoints.
- Профили сохраняют адрес, интервалы, пороги, разрешаемые типы проб, имя игры и исключения. Объединённого автоматического применения DNS/QoS/системного профиля нет: каждый требует отдельного действия.
- Сравнение производительности содержит CPU/RAM. FPS, 1% Low, frametime и GPU не реализованы без проверенного измерителя.
- Для DNS используются UDP/53; усечённый DNS-ответ отклоняется с причиной «нужен TCP». DoH/DoT не настраиваются. HTTPS test.nextdns.io характеризует только данный тест, а не все программы.
- API NextDNS проверен на fake HTTP. Список конфигураций является условной возможностью; ручной ID поддерживается. Логи ограничены одной страницей до 100 записей и отдельным разрешением.
- Применение QoS и DNS на настоящем адаптере в этой сессии не выполнялось; эффективность shaping и совместимость с конкретной редакцией Windows/драйвером не подтверждены. FACEIT AC не тестировался.
- Масштабирование 100/125/150/200% проверено в UI-harness с увеличением масштаба/шрифта. Физические мониторы с каждым из четырёх DPI не перенастраивались.

## Фактические проверки

- build.ps1, C#/.NET Framework csc, x64: успешно, 163 автоматических теста.
- UI harness: старые действия и восстановление; шейдеры; новые страницы; отсутствие разрешения на пробы; 4 масштаба; отзывчивость при ожидании.
- Опциональный `--network-read-check`: прочитаны 11 интерфейсов, TCP/UDP owner-PID endpoints и DNS automatic/static. Модули DNS Client и NetQoS найдены. Недоступное семейство адаптера выводится как ограничение.
- Опциональный `--network-local-check`: ICMP loopback Success; TCP соединение к собственному loopback listener успешно; 5 native CPU/RAM отсчётов.
- Системные DNS/QoS не изменялись. Настоящий NextDNS API key/аккаунт не использовался. Внешние игровые адреса тестами не опрашивались.

Сборка не содержит VPN, relay, драйвера, packet interception, DLL injection, оверлея или изменения защиты Windows. Нет доказательств снижения ping/роста FPS, и такие результаты не заявляются.
